# 仕様と完成条件

状態: 全体の仕様を検討しながら、0.1の基礎実装を進めている。「合意したゴール」以外は設計案であり、現在の実装状況は[対応一覧](support.md)を参照。

## 合意したゴール

1. 対象はLILYGO T-Display S3。
2. UIはHTMLファイルとCSSファイルで編集する。
3. PC上で変換・コンパイルしてファームウェアに組み込む。
4. LVGLで表現できるUIを広く記述できることを優先する。
5. UIに必要なタグ・CSSを広く扱う。小さなデモ専用の構文で完成としない。
6. 既存ライブラリを活用し、ライセンスを確認する。何でも自前実装しない。

## 対象環境案

- 標準のT-Display S3に搭載されるST7789、170×320ピクセルの液晶を対象とする。
- 縦向き170×320と横向き320×170をビルド設定で選べるようにする。
- タッチなしの標準モデルでも、物理ボタンでフォーカス移動・決定を行えるようにする。
- T-Display S3 AMOLEDなど、別ディスプレイの派生機種は別のボード設定として扱う。
- Arduino / PlatformIOとLVGLを第一候補とする。具体的なバージョンはビルド検証後に固定する。

## アーキテクチャ案

### PC上

1. 既存のHTMLパーサーで要素ツリーを作る。
2. 既存のCSSパーサーとセレクター照合ライブラリでスタイルを解決する。
3. タグ・プロパティ・値を対応表に照らして検証する。
4. LVGLの部品、スタイル、状態遷移に変換した中間表現を作る。
5. C++コード、ID参照表、状態・クラスの照合表、画像・フォントを生成する。
6. 依存バージョン、アセット由来、ライセンス通知、容量レポートを出力する。

### ESP32上

- LVGLが部品、描画、レイアウト、入力、アニメーションを担当する。
- 小さなC++連携層がIDによるアクセス、値更新、イベント通知、画面切替を担当する。
- 状態やクラスを変更するときは、生成済みの型付きデータを使う。
- HTML/CSSの文字列パーサーやJavaScriptエンジンを通常のファームウェアに含めない。
- ブラウザとのピクセル単位の一致は要求しない。

## タグの対応範囲案

全体の対応候補。現在の実装範囲は[対応一覧](support.md)で区別する。属性・制約・LVGLへの対応まで定義してから、対応済みとする。

| 分類 | タグ・機能候補 | 方針 |
| --- | --- | --- |
| 文書 | `html`, `head`, `meta`, `title`, `link`, `style`, `body` | ビルド設定、CSS読み込み、ルート画面 |
| 構造 | `div`, `main`, `section`, `article`, `header`, `footer`, `nav`, `aside` | LVGLのコンテナー |
| 文章 | `h1`–`h6`, `p`, `span`, `strong`, `b`, `em`, `i`, `small`, `br`, `hr`, `pre`, `code` | ラベル、装飾付きテキスト、区切り |
| リスト | `ul`, `ol`, `li`, `dl`, `dt`, `dd` | コンテナー・項目・番号付与 |
| 画像 | `img`, `figure`, `figcaption` | ローカルアセットの画像・キャプション |
| 操作 | `button`, `a` | ボタン、C++へのイベント、画面内・画面間の遷移 |
| フォーム | `form`, `label`, `fieldset`, `legend`, `output` | グループ、ラベル関連付け、送信・リセットイベント |
| テキスト入力 | `input`の`text`, `password`, `number`, `email`, `tel`, `url`, `search`、`textarea` | LVGLの入力部品。形式ごとの検証範囲は別途定義 |
| 選択入力 | `input`の`checkbox`, `radio`, `range`、`select`, `option`, `optgroup` | チェック、排他選択、スライダー、選択リスト |
| その他の入力 | `input`の`button`, `submit`, `reset`, `hidden` | 操作イベント・非表示データ |
| ピッカー | 日付・時刻・色の入力 | 既存部品の組み合わせ。対応typeを実装前に列挙 |
| 状態表示 | `progress`, `meter` | バー、値域、現在値 |
| 表 | `table`, `caption`, `thead`, `tbody`, `tfoot`, `tr`, `th`, `td` | 文字中心の表。セル内の複合UI・結合セルの制約を定義 |
| 開閉・重ね表示 | `details`, `summary`, `dialog` | 開閉状態、モーダル、フォーカス制御 |
| LVGL固有の部品 | スイッチ、チャート、アーク、スピナー、ローラー、キーボード、タブ、LEDなど | 標準HTMLに対応がない部品は`ui-*`カスタム要素で補う |

共通属性は`id`, `class`, `style`, `hidden`, `tabindex`など。入力属性は`value`, `disabled`, `readonly`, `checked`, `selected`, `min`, `max`, `step`, `maxlength`, `placeholder`, `required`などを対象に、部品ごとの対応表を作る。

`script`、外部Webページの実行、ブラウザのネットワークAPIは対象外。`input type="file"`など基板・ストレージ機能に依存するものは、拡張の要否を別途決める。

## CSSの対応範囲案

全体の対応候補。現在の実装範囲は[対応一覧](support.md)で区別する。各行を「プロパティ・値・単位・適用先・状態変更時の挙動」の表に展開する。

| 分類 | 対応候補 |
| --- | --- |
| 基本 | カスケード、詳細度、継承、ソース順、`!important`、カスタムプロパティ、`var()` |
| セレクター | タグ、ID、クラス、属性、複合、子孫・子・隣接・後続、グループ、基本的な構造擬似クラス |
| 状態 | `:focus`, `:focus-visible`, `:active`, `:disabled`, `:enabled`, `:checked`。部品の状態をLVGLへ対応付ける |
| 表示 | `display`, `visibility`, `opacity` |
| サイズ | `width`, `height`, `min-width`, `min-height`, `max-width`, `max-height`, `box-sizing` |
| 余白 | `margin`、`padding`と各辺指定、`gap`, `row-gap`, `column-gap` |
| Flex | `flex-direction`, `flex-wrap`, `flex-grow`, `flex-shrink`, `flex-basis`, `flex`, `justify-content`, `align-items`, `align-content`, `align-self`, `order` |
| Grid | `grid-template-columns`, `grid-template-rows`, `grid-column`, `grid-row`、間隔・配置。対応するトラック指定を明記 |
| 位置 | `position`, `top`, `right`, `bottom`, `left`, `z-index`。LVGLでの基準位置・描画順を定義 |
| はみ出し | `overflow`, `overflow-x`, `overflow-y`、スクロール、スクロールバーの装飾 |
| 背景 | `background-color`, `background-image`, `background-size`, `background-position`, `background-repeat`、グラデーション |
| 枠・影 | `border`と各辺・幅・色・線種、`border-radius`, `outline`, `box-shadow` |
| 文字 | `color`, `font-family`, `font-size`, `font-weight`, `font-style`, `line-height`, `letter-spacing`, `text-align`, `text-decoration`, `white-space`, `text-overflow`、折り返し |
| 画像 | `object-fit`, `object-position`、透過画像 |
| 変形・動き | `transform`, `transform-origin`, `transition`関連、`animation`関連、`@keyframes`。対応する変形・補間・タイミングを列挙 |
| 画面条件 | `@media`による画面サイズ・向きの条件分岐。初版はビルド対象の解像度・向きで解決する案 |
| フォント | ローカルの`@font-face`、日本語フォント、使用文字のサブセット化、動的文字の追加指定 |
| LVGL固有スタイル | インジケーター、つまみ、アーク、チャートなどの部品別スタイル。記法と対応するLVGLのpart/stateを別途定義 |

### 互換性のルール

- ブラウザと異なる既定値・レイアウトは文書化する。通常フローやインライン配置を暗黙にブラウザ互換と呼ばない。
- `px`, `%`, `em`, `rem`, `vw`, `vh`, `fr`, `auto`は適用先を明記する。単位が読めるだけでは対応済みとしない。
- FlexやGridも、LVGLに同名の機能があるだけでCSS仕様全体への対応としない。
- 継承や動的クラス変更、祖先の状態に依存する指定も、対応できる組み合わせを列挙する。
- 動的に変更できるクラス・スタイル・アセットはビルド時に登録できるようにする。
- 未対応のタグ、属性、プロパティ、値、組み合わせは、ファイル名・位置・理由を示してコンパイルエラーにする。
- HTMLパーサーが修復した誤記も診断の対象とする。

## C++ APIの責務案

具体的な関数シグネチャは未確定。

- 生成した画面の作成・破棄・切替。
- HTMLのIDによる要素へのアクセス。
- テキスト、数値、入力値、選択値、画像の更新。
- 表示、無効、チェック、フォーカスの変更。
- コンパイル済みクラスの追加・削除とスタイル再適用。
- クリック、値変更、フォーカス、フォーム操作のコールバック。
- チャートなどの部品固有データの更新。
- 入力グループと物理ボタンの接続。

LVGLの呼び出し元スレッド、コールバック中の画面破棄、要素参照の寿命もAPI契約に含める。

## 完成条件案

1. 別ファイルのHTML/CSSから、手作業で生成コードを修正せずビルドできる。
2. 合意した対応表の全項目に、変換・表示・入力・更新のうち必要な検証がある。
3. レイアウト、フォーム、日本語・画像、状態変化、画面遷移、アニメーションを含む部品カタログがある。
4. T-Display S3の実機で、描画と物理ボタン操作を確認する。
5. ホスト上での変換・診断テスト、LVGL描画の確認、ESP32向けビルドを分けて検証する。
6. 容量と性能の基準となる画面・要素数・アセットを定め、フラッシュ、内部RAM、PSRAM、更新時間を測る。
7. 同じ入力と固定した依存から再現可能に生成できる。
8. 依存一覧と必要なライセンス通知を配布物に含める。

容量・速度の数値目標は、基準画面を決めて最初の実機測定後に固定する。未測定のFPSやメモリ使用量を保証しない。

## 実装順序案

1. 対応タグ・CSS・属性・値の一覧と、既存ライブラリへの対応付けを固める。
2. パーサー群とLVGL、液晶ドライバの組み合わせを、小さな縦断サンプルで検証する。
3. コンパイラの中間表現・コード生成・診断を作る。
4. 配置・表示・入力・状態・アセット・動きの順に対応表を埋める。
5. 部品カタログ、実機検証、配布・ライセンス通知を整える。

最初のサンプルが動くことと、広い対応範囲を満たして完成することは別の到達点として管理する。
